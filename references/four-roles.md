# 四角色分工：检索 / 执行 / 校验 / 呈现

> 核心：**未来工作的单位不是"一个人用一个模型"，而是"一个人调度一组分工明确的 Agent"。** 质量提升主要来自"校验"这个独立角色，而不是提示词调优。

## 一、为什么拆（一个模型一口气干到底的问题）

```
自产自销（自己写自己查）的盲区：
  - 同一上下文里的系统性偏见查不出来（自己写错的逻辑，自己查时也"觉得对"）
  - 产出越长，后段质量越滑坡（注意力衰减），自产自销没有独立质检点
  - 提示词调优的天花板 = 同一上下文的自我纠偏能力，调到第三轮边际收益归零
```

拆分后：
- 每个角色拿到**独立指令与上下文**（校验者不知道初稿是怎么写出来的，只看产出物本身）
- 质量检查点外置：初稿可以烂，校验环节是独立闸门
- 失败可定位：错在检索（事实错）还是执行（推理错）还是呈现（表达错），返工成本不同

## 二、四角色指令模板

### 角色 1：检索（找资料）

```
输入：问题清单（每个问题一句话）
指令模板：
  "针对以下 N 个问题，只找事实，不做综合判断。
   每个事实必须带出处（来源名+链接/页码）。
   找不到就写'未找到'，不许推断补全。
   输出格式：问题 → 事实列表（每条带出处）"
输出：带出处的事实集
禁止：综合、评价、"一般来说"
```

### 角色 2：执行（产出初稿）

```
输入：问题 + 事实集（只给事实集，不给检索过程的闲聊）
指令模板：
  "只基于给定的事实集产出初稿，事实集之外的事实一律不引入。
   初稿标注：哪些段落是事实（对应事实集编号）、哪些是推理。
   不要自我检查，写出初稿就停。"
输出：初稿（带事实/推理标注）
禁止：自我校验（那是角色 3 的事）、引入事实集外信息
```

### 角色 3：校验（挑错与事实核对）——质量的关键角色

```
输入：初稿 + 事实集（独立上下文，不知道初稿是谁写的、怎么写的）
指令模板：
  "逐条核对：
   1. 初稿中每个事实声明 → 在事实集中找对应编号，找不到 = 标记【无出处】
   2. 初稿中每个推理 → 检查前提是否都在事实集中，缺前提 = 标记【前提缺失】
   3. 初稿内部一致性 → 前后矛盾 = 标记【矛盾】
   输出：差异清单（编号+位置+类型+原文+问题），不要直接改稿。"
输出：差异清单（不改稿——改稿是执行者的事，校验者只出清单）
禁止：直接改写、"感觉不对"（必须给具体类型和位置）
```

**为什么校验者不改稿**：校验者改稿 = 又变成自产自销（挑错的人顺手改，改完没人挑他的错）。流程必须回到执行者：差异清单 → 执行者修订 → 再校验（最多 2 轮，第 2 轮还不过 = 升级给人）。

### 角色 4：呈现（排版与可视化）

```
输入：校验通过的修订稿
指令模板：
  "只做呈现层：排版、结构、图表、可视化。
   禁止改动任何事实与表述（要改内容 = 回退给执行者）。
   输出：最终产出物（可展示形态：文档/页面/卡片）"
```

## 三、上下文隔离方法

```
隔离原则：下游不继承上游的"过程"，只继承上游的"产出物"
  检索 → 执行：给事实集，不给检索对话
  执行 → 校验：给初稿+事实集，不给执行对话（不知道初稿怎么写的）
  校验 → 执行（修订）：给差异清单，不给校验对话
```

实现（多 Agent/多会话场景）：
- 每个角色一个独立会话/Agent
- 交接用文件（handoff 四要素的简化版：进度=无/产出物/下一步=单一动作）
- 校验角色的会话里，初稿是"别人的作品"——指令里明确"这是待审稿件，你只出清单"

**最小成本隔离**（不想开四个会话时）：同一个模型，但**校验那一步开新会话**，把初稿和事实集当外部材料贴进去——隔离的最低要求是"校验上下文里没有写作过程"。

## 四、什么时候不用拆（小任务拆了反而慢）

```
不拆的条件（全部满足）：
  [ ] 单环节任务（只做检索 或 只做呈现，没有"写+查"组合）
  [ ] 产出 < 500 字（短到系统性盲区概率低）
  [ ] 无事实密度（不依赖外部事实，纯生成/纯排版）
  [ ] 一次性使用（不进决策、不对外、无后果）
```

**必须拆的信号**（任一满足就拆，且校验角色不可省）：
- 产出要进决策/对外（错了有后果）
- 事实密集（引用数据、引用他人观点）
- 长文（>2000 字，后段滑坡风险高）
- 重复交付（模板化任务，校验角色可沉淀成固定 checklist）

**典型错误**：为了"显得专业"把写个周报也拆四角色——小任务拆分的协调成本 > 质量收益。拆分的判据是**后果与密度**，不是仪式感。

## 五、校验角色质量标准（差异清单格式）

```markdown
# 差异清单：<稿件名>（第 N 轮）
| # | 位置 | 类型 | 原文 | 问题 | 处置建议 |
|---|---|---|---|---|---|
| 1 | §2.1 | 无出处 | "提升60%" | 事实集无对应 | 删除或补出处 |
| 2 | §3 | 前提缺失 | "因此可以…" | 前提B不在事实集 | 补前提或降级为"可能" |
| 3 | §1 vs §4 | 矛盾 | "A/B" | 前后不一致 | 统一为 A |

结论：通过 / 需修订（附修订优先级）
```

**质量判据**：
- 每条差异有位置+类型+原文（接的人不用猜说的是哪句）
- 0 条差异的校验 = 没校验（长文/事实密集稿件必有差异，"没发现问题"要反查校验指令是否够严）
- 校验轮次 ≤2：第 2 轮还有结构性差异 = 升级给人，不再循环（循环校验 = 成本失控，与 taste-gate 时间盒同构）
