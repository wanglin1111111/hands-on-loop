# 坑位清单

## 听懂就算学会

**坑**：看完文章/听完演讲/看完 demo，觉得"我懂了"，然后……没有然后。
**问题**："听懂"是输入端的完成，不是能力端的存在；不跑通，判断全是二手的（转述别人的结论），进决策就是把别人的上下文当自己的。
**对策**：硬规矩——新技术不跑通不写进方案；"听懂"的价值上限是"知道有这个东西"，下限是"能复述给别人"，两者都不产生"能跑的东西"。判断一场活动/课/教程只问一句：有没有让我手上多出一个能跑的产出。

## demo 当跑通

**坑**：看了别人的 demo 视频/演示，记下来"X 能做到 Y"，当自己跑通了。
**问题**：demo 是别人环境、别人调好的、别人挑过的成功路径；你的环境/数据/版本都可能不一样。demo 结论进方案 = 二手判断没标注"未亲测"。
**对策**：最小闭环亲自走一遍（10 分钟时间盒+单一产出）；引用 demo 结论必须标注"来源 demo，未亲测"；亲测跑通了再删标注。

## Cookbook 只留代码不留环境

**坑**：跑通了，把代码存下来当 Cookbook，环境和样例没留。
**问题**：代码离开环境就是尸体——依赖版本、Token 配置、启动顺序全在环境里；下次"复用"= 重新配置两小时（一次性 demo 的复现）。
**对策**：三件套强制（环境说明/镜像 + 最小代码 + 已知可跑样例），缺一 = 闭环没完成；复用验收三步（环境起得来/代码跑得动/样例出预期），任一不过 = Cookbook 过期要更新不是硬用。

## handoff 写方向不写唯一动作

**坑**：交接文档写"接下来优化一下性能，注意边界情况"。
**问题**：接的人拿到的是"方向"，规划成本全转嫁给接的人——重问一遍重想一遍，启动成本 2 小时；handoff 的核心价值（把上下文搬出会话窗口）没兑现，因为"下一步"还在你脑子里。
**对策**：下一步 = 动词开头的单步 + 客观完成判据（"把第 42 行阈值改 0.85，跑通 pytest -k test_foo"）；交接前 30 秒自检："接的人只看这份文档，不问任何人，能开始执行吗？"

## 校验角色自产自销

**坑**：让写初稿的同一个 Agent/同一会话"再检查一下"，或者校验者顺手把错改了。
**问题**：同一上下文里的系统性盲区查不出来（自己写错的逻辑自己查时也"觉得对"）；校验者改稿 = 挑错的人改完没人挑他的错，质量闸门形同虚设——这就是为什么"质量提升主要来自提示词调优"是错觉，提示词调到第三轮边际收益归零，因为瓶颈不是提示词是**缺乏独立检查点**。
**对策**：校验独立上下文（最低要求：校验那一步开新会话，初稿当外部材料贴进去）；校验者只出差异清单不改稿，改稿回到执行者；轮次 ≤2，第 2 轮还不过升级给人。

## Vibe Coding 选高风险环节

**坑**：最懂业务的人拿 AI 工具直接搭，一上来就选对外/资金/合规相关的系统。
**问题**：Vibe Coding 的前提是试错成本低——内部工具错了改就是了；对外/资金/合规环节错了是有后果的（客户看到 bug/资金算错/合规违规），"最懂业务"不覆盖"懂风险兜底"。
**对策**：三条件同时满足才选（高频 ✓ 低风险 ✓ 内部使用 ✓）；典型安全区：数据看板/周报生成/表单核对；过了内部验证期（用两周+有数字），再谈对外化（届时按 fde-business-embed 的兜底设计走）。

## 作品页只攒链接不攒可验证产出

**坑**：作品页是一堆"我参与了 X 项目"的链接，点进去是项目主页，找不到"你做的那部分"。
**问题**：能力的可信度迁移到"可验证的产出物"——项目主页验证不了"你"，只能验证"项目"；简历里的一句话和这种链接是同一类东西（履历描述），迁移没完成。
**对策**：每个作品留**你自己那部分**的可展示成品（截图/卡片/独立链接/可运行的最小 demo）；判据：别人 30 秒内能验证"这是你做的、它确实能跑/确实是这样"；做不到 30 秒验证的，不算作品，算"参与经历"。

## 连接不留书面描述

**坑**：加了微信/交换了名片，没留书面的能力/需求描述，后续"有事联系"再无下文。
**问题**：连接的价值 = 后续匹配的可能性；没有书面的能力/需求描述（Profile），对方脑子里对你的印象 3 个月衰减到零，匹配无从发生——"加了微信再无下文"不是运气差，是连接没有资产化。
**对策**：数字名片/一页能力介绍**随时可发**（不是临时现写）：能做什么/做过什么（带作品链接）/需要什么；遇到人就交换；判据：三个月后对方（或你自己）只看这份文档，还能知道你是什么人、能匹配什么。

## 时间盒超时变无限重试

**坑**：10 分钟闭环超了，"再试试应该就通了"，40 分钟过去还在配环境。
**问题**：无限重试 = 把最小闭环变成两小时配置，这正是原文点名的门槛（"门槛不在知识，在开始前的那两小时配置"）；而且超时的信息价值被浪费——卡点本身（环境/文档/样例哪里有问题）是该工具最重要的真实信号。
**对策**：到点停，记录门槛缺陷（卡点/现象/文档怎么说/解法/信号）；超时产出 = 缺陷记录，不是"再试试"；同类缺陷记录 3 次以上 = 该工具预置质量差的客观证据，评估时直接引用。

## 四角色拆给小任务（仪式感拆分）

**坑**：写个 300 字周报也开四个会话走检索→执行→校验→呈现。
**问题**：拆分的协调成本（四次交接+四次上下文重建）> 短小任务的质量收益；系统性盲区在 500 字纯生成文本里的概率低，拆了是表演流程不是质量流程。
**对策**：不拆判据四条件（单环节/<500 字/无事实密度/一次性）全满足才不拆；必须拆的信号（进决策/事实密集/长文/重复交付）任一满足就拆且校验不可省；判据是**后果与密度**，不是"显得专业"。
