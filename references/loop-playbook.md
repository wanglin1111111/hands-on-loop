# 最小闭环 Playbook：10 分钟怎么设计

> 核心：**最小闭环 = 时间盒（≤10 分钟）+ 单一明确产出。** "研究一下"不是闭环；"跑通"是闭环。

## 一、单一产出的定义法

产出必须满足三个条件（缺一 = 不是"跑通"）：

```
1. 可打开/可执行：一个能打开的看板、一条返回 200 的接口、一次成功的调用
2. 可判定：跑没跑通有客观判据（页面出来了/返回码对了/输出匹配预期），不是"感觉通了"
3. 单一：只证明一件事（这个工具能干什么），不证明整个方案
```

**反例**：
- "了解 X 的基本原理" → 没有产出物
- "搭一个 X 的完整 demo" → 不单一，10 分钟做不到，必然超时间盒
- "跑通 X 并评估是否值得用" → 评估是跑通之后的事，不要塞进闭环

**正例格式**：

```
最小闭环：<技术名> 的 <单一能力> 跑通
  产出物：<具体到能指着说"这就是"的东西>
  判据：<客观判据，一句话>
  时间盒：10 分钟
  前提：<预置环境/样例/Token 是否就绪>
```

## 二、时间盒参数

| 项 | 参数 | 说明 |
|---|---|---|
| 闭环本身 | ≤10 分钟 | 原文标准（工坊敢承诺 10 分钟）；超过说明产出定义太大或环境没预置 |
| 环境预置 | 提前做完，不算进 10 分钟 | 门槛在开始前的配置；把预置时间算进闭环 = 永远跑不通 |
| 超时处理 | 到点停，记录门槛缺陷 | 超时 = 该工具的真实信号（环境/文档/样例问题），记录比硬撑有价值 |

**10 分钟跑不通的分流**：
```
卡在哪？
  ├─ 环境配置 → 门槛缺陷（记录：哪一步卡住、卡多久、文档有没有说）
  ├─ 样例跑偏 → 样例缺陷（记录：输入什么、预期什么、实际什么）
  ├─ 能力不足（我读不懂文档/报错）→ 能力门槛（记录：需要补什么知识）
  └─ 到点了但快通了 → 不算跑通，记"9 分钟状态"，下次从断点续
```

**关键纪律**：超时的产出是"门槛缺陷记录"，不是"我再试试"——无限重试 = 把 10 分钟闭环变成两小时配置，这正是原文说的"门槛不在知识，在开始前的那两小时配置"。

## 三、门槛缺陷记录模板

```markdown
# 门槛缺陷记录：<技术名> <日期>
- 卡点：第 __ 步（<步骤描述>）
- 现象：<报错/卡住的具体表现>
- 文档怎么说：<有写/没写/写了但和实际不符>
- 解法：<怎么解的/没解成>
- 耗时：<从开始到卡住的分钟数>
- 信号：<该工具的预置质量如何：开箱即跑/小修能跑/大改才跑>
```

**用途**：
1. 评估该工具的真实落地成本（宣传的"10 分钟" vs 实际的"10 分钟 + 40 分钟修环境"）
2. 同类工具横向对比的客观维度
3. 自己 Cookbook 的一部分（下次帮别人跑通时直接给解法）

## 四、Cookbook 三件套完整模板

```markdown
# Cookbook: <技术名> <版本>（<日期> 跑通）
## 1. 环境
  依赖：python 3.x / node 2x / 镜像地址 <docker>
  一键启动：<命令，复制就能跑>
  Token/凭证：<从哪拿、环境变量名，不写具体值>
## 2. 最小代码
  <可复制代码块，改 3 行以内能跑，关键行注释>
## 3. 已知可跑的输入样例
  输入：<具体输入>
  预期输出：<具体到能对比的输出>
## 附：踩坑记录
  坑 1：<现象> → <解法>
  坑 2：<现象> → <解法>
```

### 复用验收法（下次用 Cookbook 时）

复用 ≠ 重新学习，验收三步（每步 ≤3 分钟，共 ≤10 分钟）：
```
1. 环境起得来？（一键启动命令跑一遍）
2. 代码跑得动？（复制最小代码跑一遍）
3. 样例出预期？（输入样例，对比预期输出）
三步全过 = 10 分钟复用成功
任一不过 = Cookbook 过期（版本变了），更新三件套而不是硬用
```

**判据**：攒够 10 份 = 你的"工坊"——你可以对别人承诺"10 分钟跑通"了。这是原文"降低门槛"的同构：你成为别人的预置环境。

## 五、"听懂"到"跑通"的转化检查

判断一次技术活动/课程/教程值不值（原文标准）：

```
参加前：这个活动/课/教程会让我手上多出什么能跑的东西？
  答不出 → 不参加（信息差用公开资料补）
  答得出 → 参加，并带着"10 分钟闭环"设计去（现场或会后 48 小时内跑）

参加后 48 小时：闭环跑了吗？
  跑了 → Cookbook +1
  没跑 → "听懂了"，价值归零（和没参加差不了多少）
```

**与 ai-chain-embed 的 72 小时落地同构**：参会价值在于手上多了什么能跑/能展示的东西，不在于记得多少。时间窗内不落地 = 没落地。
