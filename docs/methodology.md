# 技术传播的最小单位是"亲手跑通"，不是"听懂"

> 源材料：AI 开发者大会（创想舞台 + 双工坊 + 展区）拆解
> 本文为 `hands-on-loop` 技能的方法论底座；可执行工作流见 `../SKILL.md`。

## 一、奥卡姆剃刀：剥掉所有装饰后，只剩一句话

**主题 = 技术传播的最小单位是"亲手跑通"，不是"听懂"。**

把所有项目名（AReaL、ms-swift、OceanBase、DB-GPT…）、所有环节（舞台、工坊、展区、碰碰墙）、所有周边（集章、胸牌、机器人合唱）全部剃掉，它们只是变量；不变的常量只有一个——**让开发者在最短时间内，用预置环境和现成 Cookbook，把 AI 从"知道"变成"跑通"。** 文章最后一句已经自证："最好的技术传播，永远是实战。"

## 二、核心提炼

**①【实战优先】听懂不算数，跑通才算数**

创想舞台讲 30 位讲者、18 个项目、两场动手实践，但真正的重心在工坊——10 分钟从"看懂"到"跑通"一个产品级资讯看板。判断一场技术活动、一门课、一篇教程的价值，只问一句：**有没有让你手上产生一个能跑的产出。**

**②【降低门槛】预置环境 + Cookbook + 充足 Token = 参与的真正门票**

工坊敢承诺"10 分钟跑通"，靠的不是内容简单，而是把环境配置、脚手架、算力这三道拦路虎提前清掉。**门槛不在知识，在开始前的那两小时配置。**

**③【记忆不中断】跨会话、跨 Agent 的工作接续，是 Agent 落地的下一个分水岭**

第二场工坊跑的是"跨会话记忆接续"。单点 Agent 已经不够用了，能不能把上下文、状态、进度交出去，决定了 Agent 是玩具还是生产力。

**④【Vibe Coding】最懂业务的人开始自己写代码**

公益骨干用 AI 编程做科普应用——技术不再是瓶颈，领域理解才是。谁最懂场景，谁就该是那个动手的人。

**⑤【作品即简历】展示方式正在被重写**

Bonjour 用"作品"自我介绍，DINQ 用自然语言描述候选人再匹配项目与代码。**能力的可信度从"履历描述"迁移到"可验证的产出物"。**

**⑥【异质协作】4 个 bot 分工完成一次店庆策划**

Avernet 演示的是多角色 Agent 协作，不是单模型问答。未来工作的单位不是"一个人用一个模型"，而是"一个人调度一组分工明确的 Agent"。

**⑦【连接可复用】把偶遇变成资产**

碰一碰胸牌交换联系方式、Agent 相亲角张贴 Profile——社交被产品化了：先有可交换的数字名片，再有连接；先有书面的能力/需求描述，再有匹配。

## 三、未来现实行动指南：怎么塞进你的日常工作流

**① 立一条硬规矩：新技术不跑通不写进方案**

接触任何新模型、新框架，先设一个"10 分钟最小闭环"——明确的单一产出（一个能打开的看板、一条跑通的接口、一次成功的调用）。跑通=可以评估；跑不通=对它的所有判断都是二手的，不许进决策。

**② 自建 Cookbook，把一次性 demo 变成可复用脚手架**

每次跑通后强制留三样东西：**预配置环境说明（或镜像）、可复制的最小代码、一个已知可跑的输入样例。** 这一步做与不做，决定了你下一次是花 10 分钟还是两小时。攒够 10 份，你就有了自己的"工坊"。

**③ 给 Agent 写交接文档，而不是开新会话重讲一遍**

仿"记忆不中断"：任何跨天、跨人、跨工具的任务，落一份 handoff 文档——**当前进度、已试过的失败路径、下一步唯一动作、约束条件。** 把"上下文"从人脑和会话窗口里搬出来，变成可传递的文件。这是多 Agent 协作能跑起来的前提。

**④ 用分工代替全能：把任务拆成 4 个角色**

参照 4 个异构 bot 协作：拆成**检索（找资料）、执行（产出初稿）、校验（挑错与事实核对）、呈现（排版与可视化）**四个独立环节，各自给独立指令和上下文，别让一个模型一口气干到底。**质量提升主要来自"校验"这个独立角色，而不是提示词调优。**

**⑤ 让最懂业务的人直接动手**

你所在的岗位里，谁最懂场景，谁就该拿 AI 工具自己搭小应用，而不是写需求文档等开发排期。先挑一个**高频、低风险、内部使用**的痛点（数据看板、周报生成、表单核对），让它成为第一个 Vibe Coding 产物。

**⑥ 把你的产出作品化，把你的连接资产化**

两件小事：其一，任何做完的事都留一个可展示的成品（截图、卡片、链接），攒成作品页，替代"简历里的一句话"；其二，准备一份随时可发的数字名片/一页能力介绍，遇到人就交换——把偶遇从"加了微信再无下文"变成"有据可查的连接"。

**⑦ 日常节奏建议（可直接照抄）**

每周挑 1 个新技术走"10 分钟闭环"→ 跑通则补进 Cookbook 库；每月用多 Agent 分工完整交付 1 个真实任务；每季度更新一次作品页与能力简介。**判断标准始终只有一个：这个月你手上多出了几个能跑、能展示的东西。**
